Принято. Гарнизонные пушки и пушки-подкрепления не различаются после основного боя; `defend1vall` возвращает единый `newcannons`. Тогда финализирую Часть 3.

# Часть 3. Этап перемещения

## 3.1. Место в последовательности

Выполняется внутри `applyOrders` после экономической фазы (Часть 2) и до основного боя (Часть 4). К моменту начала этапа:

- `tile.tmpr_owner == tile.owner`.
- `tile.retreat_province` заполнен через `Order5`.
- `tile.incoming[i]` и `tile.arrived[i]` — пустые `ArmyGroup` для всех `i` (инициализированы в начале `applyOrders`).
- `tile.reinforcements` — нулевая `Army`.
- `Order6`, `Order7`, `Order8` ещё не агрегированы.

## 3.2. Задействованные поля `Tile`

```text
incoming: Array<ArmyGroup>   // incoming[i] — поток из neighbours[i] в этот тайл
arrived: Array<ArmyGroup>    // arrived[i]  — результат потока incoming[i]
reinforcements: Army         // армии, прибывшие в этот тайл в фазе перемещения
```

Семантика:

- `incoming[i].army` — армия, идущая из `neighbours[i]` в этот тайл. Сливается из нескольких `Order6` одной страны по маршруту `neighbours[i] → этот тайл`.
- `incoming[i].support` — армии, поддерживающие этот переход (результат агрегации `Order7`).
- `arrived[i]` — то, что осталось от `incoming[i]` после `movement_phase`. Для потоков без боя — копия `incoming[i]` без изменений.
- `reinforcements` — армии, физически находящиеся в тайле и участвующие в основном бою как подкрепления (пехота без бонуса обороны, пушки полноправны).

## 3.3. Агрегация `Order6` и `Order7`

Агрегация выполняется один раз, до этапа перемещения. Порядок агрегации не важен: все операции — `append` или слияние, результат от порядка не зависит.

### `aggregate_Order6(state, order)`

```text
aggregate_Order6(state, order):
    if order.owner != order.from.tmpr_owner:
        return                          // невалидно: страна не владеет from
    if order.to not in order.from.neighbours:
        return                          // невалидно: не соседи
    if order.infantry == 0 and order.cannons == 0:
        return                          // невалидно: пустой приказ

    i = index_of(order.to, order.from.neighbours)
    ag = order.to.incoming[i]

    if ag.army.infantry == 0 and ag.army.cannons == 0:
        // Случай 1: армии ещё нет — создаём
        ag.army = Army {
            infantry: order.infantry,
            cannons:  order.cannons,
            origin:   order.from,
            losedinfantry: 0,
            losedcannons:  0
        }
    else:
        // Случай 2: армия уже есть — проверяем, что origin и owner совпадают
        if ag.army.origin != order.from:
            return                      // невалидно: конфликт двух стран по одному маршруту
        ag.army.infantry += order.infantry
        ag.army.cannons  += order.cannons
```

**Замечание.** В `incoming[i].army` может быть только одна армия, потому что по одному маршруту `neighbours[i] → этот тайл` может идти только одна страна: `from.tmpr_owner` детерминированно определяет владельца. Если от двух разных стран приходят `Order6` с одним `(from, to)`, второй игнорируется. Внутри одной страны несколько `Order6` с одним `(from, to)` сливаются в одну армию.

### `aggregate_Order7(state, order)`

```text
aggregate_Order7(state, order):
    if order.owner != order.from.tmpr_owner:
        return
    if order.target_from not in order.target_to.neighbours:
        return                          // невалидно: не соседи
    if order.infantry == 0 and order.cannons == 0:
        return

    i = index_of(order.target_from, order.target_to.neighbours)
    a = Army {
        infantry: order.infantry,
        cannons:  order.cannons,
        origin:   order.from,
        losedinfantry: 0,
        losedcannons:  0
    }
    order.target_to.incoming[i].support.push(a)
```

Важно: `order.from` (где физически стоит поддержка) и `order.target_from` (начало поддерживаемого перехода) могут быть **разными** тайлами. Если они совпадают, поддержка идёт из того же тайла, откуда идёт армия; если нет — поддержка идёт из соседнего или удалённого тайла.

### `aggregate_Order8(state, order)`

Агрегация `Order8` выполняется здесь же, но используется в основном бою (Часть 4):

```text
aggregate_Order8(state, order):
    if order.owner != order.from.tmpr_owner:
        return
    if order.target != order.from and order.target not in order.from.neighbours:
        return                          // цель — сам тайл или сосед
    if order.infantry == 0 and order.cannons == 0:
        return

    a = Army {
        infantry: order.infantry,
        cannons:  order.cannons,
        origin:   order.from,
        losedinfantry: 0,
        losedcannons:  0
    }
    order.target.defenders.support.push(a)
```

### Порядок агрегации

Все приказы одного типа обрабатываются в порядке возрастания `owner.id`, затем (для `Order6` и `Order7`) по возрастанию `index_of` в массиве `neighbours`. Внутри одного приказа порядок не важен.

## 3.4. `distribute_support_losses`

```text
distribute_support_losses(support: Array<Army>, target_infantry, target_cannons) -> void:
    // ---------- infantry ----------
    total_inf = sum(a.infantry for a in support)
    loss_inf  = total_inf - target_infantry
    if loss_inf < 0:
        loss_inf = 0

    if loss_inf > 0 and total_inf > 0:
        allocs = []
        for a in support:
            exact = loss_inf * a.infantry / total_inf
            base  = floor(exact)
            allocs.push({ army: a, alloc: base, rem: exact - base })

        left = loss_inf - sum(x.alloc for x in allocs)

        sort allocs by (x.rem desc, x.army.origin.id asc)

        for i in 0..left-1:
            allocs[i].alloc += 1

        for x in allocs:
            x.army.infantry      -= x.alloc
            x.army.losedinfantry += x.alloc

    // ---------- cannons ----------
    total_can = sum(a.cannons for a in support)
    loss_can  = total_can - target_cannons
    if loss_can < 0:
        loss_can = 0

    if loss_can > 0 and total_can > 0:
        allocs = []
        for a in support:
            exact = loss_can * a.cannons / total_can
            base  = floor(exact)
            allocs.push({ army: a, alloc: base, rem: exact - base })

        left = loss_can - sum(x.alloc for x in allocs)

        sort allocs by (x.rem desc, x.army.origin.id asc)

        for i in 0..left-1:
            allocs[i].alloc += 1

        for x in allocs:
            x.army.cannons      -= x.alloc
            x.army.losedcannons += x.alloc
```

Инварианты после вызова:

- `sum(a.infantry for a in support) == target_infantry`.
- `sum(a.cannons for a in support) == target_cannons`.
- Все `a.infantry >= 0`, `a.cannons >= 0`.

Если `target_infantry > total_inf` или `target_cannons > total_can`, потери обнуляются (защитная проверка, в норме не должно случаться).

## 3.5. `movement_phase`

```text
movement_phase(g1: ArmyGroup, g2: ArmyGroup) -> (ArmyGroup, ArmyGroup):

    infantry1  = g1.army.infantry
    cannons1   = g1.army.cannons
    infantry12 = sum(a.infantry for a in g1.support)
    cannons12  = sum(a.cannons  for a in g1.support)

    infantry2  = g2.army.infantry
    cannons2   = g2.army.cannons
    infantry21 = sum(a.infantry for a in g2.support)
    cannons21  = sum(a.cannons  for a in g2.support)

    (
        activeinfantry1,  activecannons1,  passiveinfantry1,  passivecannons1,
        activeinfantry12, activecannons12,
        activeinfantry2,  activecannons2,  passiveinfantry2,  passivecannons2,
        activeinfantry21, activecannons21
    ) = movement_phase_scalar(
        infantry1, cannons1, infantry12, cannons12,
        infantry2, cannons2, infantry21, cannons21
    )

    // --- g1 ---
    g1.army.infantry = activeinfantry1
    g1.army.cannons  = activecannons1
    g1.army.origin.reinforcements.infantry += passiveinfantry1
    g1.army.origin.reinforcements.cannons  += passivecannons1

    distribute_support_losses(g1.support,
        target_infantry = activeinfantry12,
        target_cannons  = activecannons12
    )

    // --- g2 ---
    g2.army.infantry = activeinfantry2
    g2.army.cannons  = activecannons2
    g2.army.origin.reinforcements.infantry += passiveinfantry2
    g2.army.origin.reinforcements.cannons  += passivecannons2

    distribute_support_losses(g2.support,
        target_infantry = activeinfantry21,
        target_cannons  = activecannons21
    )

    return (g1, g2)
```

`movement_phase_scalar` — функция из исходного документа, реализуется как есть, без изменений.

Замечания:

- Отступившие (`passiveinfantry`/`passivecannons`) идут в `reinforcements` своего origin-тайла. `origin` здесь — тайл, из которого армия вышла на этапе перемещения.
- Потери поддержки распределяются пропорционально через `distribute_support_losses` и фиксируются в `losed*` соответствующих `Army`. Выжившие support-юниты остаются в своих `origin` (физически) и учитываются в основном бою как обычные армии.

## 3.6. `resolve_movement_phase`

Драйвер этапа перемещения. Обходит все пары соседних тайлов в детерминированном порядке.

```text
resolve_movement_phase(state) -> void:
    pairs = []
    for A in state.tiles:
        for B in A.neighbours:
            if A.id < B.id:
                pairs.push((A, B))
    sort pairs by (A.id asc, B.id asc)

    for (A, B) in pairs:
        process_movement_pair(A, B)
```

```text
process_movement_pair(A: Tile, B: Tile) -> void:
    i_AB = index_of(B, A.neighbours)
    i_BA = index_of(A, B.neighbours)

    gAB = B.incoming[i_AB]     // поток A → B
    gBA = A.incoming[i_BA]     // поток B → A

    a_empty = (gAB.army.infantry == 0 and gAB.army.cannons == 0)
    b_empty = (gBA.army.infantry == 0 and gBA.army.cannons == 0)

    if a_empty and b_empty:
        return

    if A.tmpr_owner == B.tmpr_owner:
        // Дружественные тайлы, боя нет. Армии проходят насквозь.
        B.arrived[i_AB] = gAB
        A.arrived[i_BA] = gBA
        return

    if not a_empty and not b_empty:
        // Встречное движение врагов — бой на этапе перемещения.
        (gAB_new, gBA_new) = movement_phase(gAB, gBA)
        B.arrived[i_AB] = gAB_new
        A.arrived[i_BA] = gBA_new
        return

    if not a_empty:
        // Только A → B, боя нет.
        B.arrived[i_AB] = gAB
        return

    // Только B → A, боя нет.
    A.arrived[i_BA] = gBA
```

Замечания:

- `gAB` / `gBA` — это ссылки на элементы массивов `incoming`, поэтому модификации в `movement_phase` применяются непосредственно к полям `Tile`.
- Если у потока есть только поддержка, но нет армии (`a_empty == true`), поток считается пустым и не обрабатывается. Поддержка при этом остаётся в `incoming[i].support`; её потери на этапе перемещения нулевые, и она будет учтена в основном бою как поддержка своего origin.
- Порядок обхода пар детерминирован, но бои локальны и не зависят от порядка обработки (силы сторон определяются состоянием на начало хода, а результаты записываются в отдельные `arrived` и `reinforcements`).

## 3.7. Консолидация перед основной фазой

После того как все пары обработаны, `arrived[]` содержит результаты потоков. Перед основным боем выполняется консолидация `arrived` в `reinforcements` и `defenders.support` для дружественных потоков:

```text
consolidate_arrived(state) -> void:
    for T in state.tiles:
        for i in 0..length(T.neighbours)-1:
            ag = T.arrived[i]
            if ag.army.infantry == 0 and ag.army.cannons == 0 and length(ag.support) == 0:
                continue

            owner_id = ag.army.origin.tmpr_owner.id
            if owner_id == T.tmpr_owner.id:
                // Дружественный поток — вливается в оборону тайла.
                T.reinforcements.infantry += ag.army.infantry
                T.reinforcements.cannons  += ag.army.cannons
                for s in ag.support:
                    T.defenders.support.push(s)
                T.arrived[i] = empty_ArmyGroup()
```

После консолидации:

- `T.reinforcements` содержит все дружественные армии, прибывшие в `T` в фазе перемещения (в том числе отступившие в свой origin).
- `T.defenders.support` содержит поддержку обороны из `Order8` и поддержку движения, чей поток был дружественным.
- `T.arrived[i]` для вражеских потоков содержит армии-атакующие.

Вражеские потоки в `arrived` обрабатываются в `main_phase` (Часть 4).

## 3.8. Инварианты после этапа перемещения

- Для каждого `T`: `length(T.incoming) == length(T.arrived) == length(T.neighbours)`.
- Для каждого `T` и `i`: `T.incoming[i]` может быть непустым — это агрегированные приказы, до обработки в основном бою.
- После `consolidate_arrived`: для каждого `T` и `i` либо `T.arrived[i]` пуст (дружественный поток влит), либо `T.arrived[i].army.origin.tmpr_owner != T.tmpr_owner` (вражеский поток).
- Все `army.losedinfantry`, `army.losedcannons` неотрицательны.
- `T.reinforcements.infantry >= 0`, `T.reinforcements.cannons >= 0`.

## 3.9. Примеры

### Пример 1: встречный бой 1v1 без поддержки

Старт:

- `A.tmpr_owner = C0`, `B.tmpr_owner = C1`.
- `A.defenders.army.infantry = 1`, `B.defenders.army.infantry = 1`.
- `Order6 { owner: C0, from: A, to: B, infantry: 1 }`.
- `Order6 { owner: C1, from: B, to: A, infantry: 1 }`.

После агрегации:

- `B.incoming[index_of(A)].army = { infantry: 1, origin: A }`.
- `A.incoming[index_of(B)].army = { infantry: 1, origin: B }`.

`process_movement_pair(A, B)`:

- `A.tmpr_owner != B.tmpr_owner`, обе стороны непусты → `movement_phase`.
- В `movement_phase_scalar`: `Damage1 = 0`, `Damage2 = 0`, `Power1 = 1`, `Power2 = 1`.
- Фаза столкновения: `newinfantry21 = 0`, `newinfantry2 = 0`, `retreat2 = 1`; `newinfantry12 = 0`, `newinfantry1 = 0`, `retreat1 = 1`.
- Обе стороны имеют 0 активной пехоты → «Победа1» (или «Победа2» — обе стороны равны, но код выберет одну из веток; в данном случае `newinfantry1 == 0 && newinfantry12 == 0`, значит, ветка «Победа1» не сработает из-за `else`... здесь детерминизм зависит от реализации `movement_phase_scalar`).

Результат:

- `A.reinforcements.infantry += 1` (retreat1).
- `B.reinforcements.infantry += 1` (retreat2).
- `A.arrived[index_of(B)]` и `B.arrived[index_of(A)]` — пустые ArmyGroup.

После `consolidate_arrived`: ничего не меняется, потому что `arrived` пусты.

В основном бою обе стороны будут защищать свои тайлы с гарнизоном `1` + `reinforcements.infantry = 1` (итого 2 пехоты без бонуса у reinforcements).

### Пример 2: встречный бой с поддержкой

Старт:

- `A.tmpr_owner = C0`, `B.tmpr_owner = C1`, `C` — сосед A.
- `Order6 { owner: C0, from: A, to: B, infantry: 1 }`.
- `Order6 { owner: C1, from: B, to: A, infantry: 2 }`.
- `Order7 { owner: C0, from: C, target_from: A, target_to: B, infantry: 1 }`.

После агрегации:

- `B.incoming[index_of(A)].army = { infantry: 1, origin: A }`.
- `B.incoming[index_of(A)].support = [{ infantry: 1, origin: C }]`.
- `A.incoming[index_of(B)].army = { infantry: 2, origin: B }`.

`movement_phase`:

- `infantry1 = 1`, `infantry12 = 1`, `infantry2 = 2`, `infantry21 = 0`.
- `Damage1 = 0`, `Damage2 = 0`.
- `Power1 = 1`, `Power2 = 2`.
- Фаза столкновения: `newinfantry21 = 0`, `newinfantry2 = 0`, `retreat2 = 2`; `newinfantry12 = 0`, `newinfantry1 = 0`, `retreat1 = 1`.
- Сторона 1: `newinfantry1 + newinfantry12 = 0` → ветка для стороны 1 не сработает как «Победа1».
- Сторона 2: `newinfantry2 + newinfantry21 = 0` → тоже 0.

Обе стороны без активной пехоты → «всё решают пушки» (но пушек нет) → обе стороны остаются с `activecannons = 0`.

Результат:

- `A.reinforcements.infantry += 1` (retreat1).
- `B.reinforcements.infantry += 2` (retreat2).
- `g1.support` получает потери? `activeinfantry12 = 0` (по коду — support вернулся 0). `distribute_support_losses` даст потери `1 - 0 = 1`, то есть support-`Army` из C уничтожен.
- `g2.support` пуст.

После `consolidate_arrived`: оба `arrived` пусты.

В основном бою у A и B будут пустые гарнизоны (все ушли и вернулись в `reinforcements`), а `defenders.army.infantry` — исходные значения (1 у A, 1 у B).
